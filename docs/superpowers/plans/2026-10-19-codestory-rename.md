# codeStory Rename Plan

**Goal:** Rename the product diffStory → codeStory everywhere it is live (app, package, skill, Claude plugin,
Zed extension, macOS app, data folders, docs that describe the current product), and keep every old name
working through migrations so nobody loses saved stories, settings, or an installed skill.

**Why:** The app now explains code with no diff (code stories), so "diff" no longer names it. The user asked
for a full rename (2026-10-19) and opted out of design questions.

## Names (decided)

| Old | New | Where |
| --- | --- | --- |
| `diffStory` | `codeStory` | display brand, prose, UI copy, titles |
| `DiffStory` | `CodeStory` | type-ish names, the macOS app dir `macos/DiffStoryApp` → `macos/CodeStoryApp` |
| `diffstory` | `codestory` | npm `@naveedinno/codestory`, plugin `codestory@codestory`, Zed id, skill `codestory-storyteller`, file names, APP_NAME |
| `DIFFSTORY` | `CODESTORY` | env vars, `__CODESTORY_DATA__` payload id |
| `.diffstory/` (per repo) | `.codestory/` | DATA_DIR |
| `~/.diffstory/` (app home) | `~/.codestory/` | recents, settings, story selection, verification receipts |
| `naveedinno/diffStory` | `naveedinno/codeStory` | GitHub URLs in README, badges, plugin docs, package.json |

Keep unchanged: the `ds-` CSS / storage / data-attribute prefixes; the phrases "diff story" and "code story"
(two kinds of story); historical records: `docs/research/**`, `docs/superpowers/**` (except this plan),
`docs/ui-atlas/**`, `plans/**`, `.claude-design/**`, `.better-ui-app/**`, `docs/diffstory-logo-directions.html`.
`dist/` is regenerated by `npm run build`, never hand-edited.

## Compatibility (each needs a test that fails first)

1. **Per-repo data:** `migrateLegacyDataDir(repo)` in a small new module. If `<repo>/.diffstory/` exists,
   merge-move it into `<repo>/.codestory/`: a missing target entry is renamed over; directories merge
   recursively; on a file conflict the `.codestory` copy wins and the old file is left in place; empty old
   directories are removed; nothing is ever deleted that was not moved. Also, for every line of the repo's
   `.gitignore` that mentions `.diffstory`, ensure the same line with `.codestory` exists (idempotent,
   appended). Call it wherever the server opens a repo (boot with a repo, `openSession` callers, the
   recent-repo restore) before anything reads `.codestory/`.
2. **App home:** `migrateLegacyHome(home)`: copy (never move or delete) `recents.json`, `settings.json`,
   `story-selection.json`, and `verification/` from `~/.diffstory/` to `~/.codestory/` when the new entry is
   missing. Never touch `~/.diffstory/src` (an older install may run from it). Call once at server start.
3. **Checker CLI (read-only):** when `<repo>/.codestory/` is missing and `<repo>/.diffstory/` exists,
   `defaultStories()` and `readPreferences()` read from `.diffstory/`. It still never writes.
4. **Skills:** `STORYTELLER_SKILL = 'codestory-storyteller'`; the retired names become a list,
   `['review-tour', 'diffstory-storyteller']`, handled exactly like `review-tour` is today (status reports
   `legacyInstalled`; `updateSkills` removes retired copies). Update the client copy that explains a retired
   skill so it names the right rename. `skills/diffstory-storyteller` moves to `skills/codestory-storyteller`
   (git mv), and every path that points at it (STORY_CHECKER in `src/agent.ts`,
   `scripts/build-skill-checker.mjs`, install scripts, plugin manifest, tests) follows.
5. **Env vars:** runtime variables a user may already have set read `CODESTORY_X` first, then `DIFFSTORY_X`
   (at least `CODEX_BINARY` and `PROJECT_PATH`); script- and test-only variables are renamed outright.
6. **Concept-page bridge:** the postMessage type `'diffstory:key'` becomes `'codestory:key'` on both sides
   (`src/concept-page.ts` shim and the review engine).
7. **Skill triggers:** the skill `description` keeps triggering on the old wording: it names codeStory and
   still mentions "diffStory" / "diff story" requests, and stays within the SKILL.md 520-line cap.

## Steps

1. Bulk rename in live files (`git grep -il diffstory`, minus the keep list), case by case per the table,
   and `git mv` every live path whose name contains diffstory/DiffStory (skill dir, macOS app dir,
   `zed-extension/server/diffstory-mcp.mjs`, `assets/demo/diffstory-*.png`, any test or script file).
   Update `package-lock.json`'s own name fields to match `package.json`.
2. Zed extension: id `codestory`, name `codeStory`, MCP prompt `codestory`, tool `start_codestory`,
   server file `codestory-mcp.mjs`, crate/package names; update its tests and `scripts/install-zed-integration.sh`.
3. macOS (Tauri): crate, `productName`, window title, `identifier` (mirror the current one with codestory),
   Info.plist `CFBundleName`/identifier/executable, loading page copy; `scripts/install-macos-app.sh` installs
   `codeStory.app` and, if `/Applications/diffStory.app` exists, removes it after a successful install with a
   printed note (it is replaced, not kept beside).
4. Compatibility items 1–7 with tests first.
5. Docs that describe the current product: README (install commands, plugin commands
   `/plugin marketplace add naveedinno/codeStory` and `/plugin install codestory@codestory`, badges, URLs),
   CONTRIBUTING, SECURITY, LICENSE notice, `.github/**`, `docs/story-schema.md`, `docs/RELEASE.md`,
   `docs/STRANGER_TEST.md`, `DESIGN_MEMORY.md`, `.claude/launch.json`, `examples/`, `eval/` code (not past
   eval results). CHANGELOG: one new Unreleased entry "Renamed diffStory to codeStory …" describing the
   migrations; rename the brand in existing Unreleased entries.
6. Verify (all must pass): `npm run check`; `npm run check:zed`; `cargo check --manifest-path
   macos/CodeStoryApp/Cargo.toml` if a Rust toolchain is present (report if not); and a residual scan:
   `git grep -il diffstory -- . ':!dist'` lists only the keep list, the compatibility code and its tests,
   and the CHANGELOG rename entry.

## Out of the implementer's hands

Commits, `gh repo rename`, the git remote URL, pushing, and installing anything into `~` are done by the
session owner after review.
