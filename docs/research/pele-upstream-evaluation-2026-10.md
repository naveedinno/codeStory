# Pele upstream evaluation

Checked 2026-10-20. This report covers upstream documentation, published-package probes, source, releases, and test infrastructure. Application integration and performance measurements are outside this report.

## Assessment

Pele is a credible replacement renderer for a controlled Mermaid-syntax corpus, especially where CSS theming, synchronous rendering, small imports, and removing runtime dependencies matter. It is not a behavior-identical replacement for Mermaid.js: drawing, configuration, labels, callbacks, plugins, and mounting differ. Its recent release history and open rendering issues justify an exact version pin, corpus-based visual checks, and an easy rollback. Falling back only when rendering throws cannot catch accepted diagrams whose labels or configuration change silently.

## What is attractive

- Package metadata confirms no production dependencies, TypeScript declarations, ESM, browser-global output, and Node `>=20`. `pele/core` plus registered diagram modules and `pele/lazy` allow narrower initial imports than the full renderer. The full entry explicitly has side effects, so importing it includes registration for every type; it is not equivalent to importing only flowchart support. [package.json](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/package.json), [entry point](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/src/index.ts).
- Rendering is synchronous and returns SVG plus dimensions and link metadata. Browser mounting adds resize/font handling, update/destroy lifecycle, optional sanitization, and zoom. CSS custom properties let colors change without regeneration. SVG text avoids arbitrary HTML label elements. [API](https://pele.run/api), [theming source documentation](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/website/src/content/docs/theming.md).
- MIT licensing permits commercial integration; preserve the included notices. The distributed license also includes the ISC notice for the Lucide reset icon. Mermaid-derived compatibility specs and grammar files have their own MIT attribution. [LICENSE](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/LICENSE), [README licensing](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/README.md#license).

## Compatibility boundaries

Upstream targets all diagram types built into Mermaid **12.1.0**, including flowchart, sequence, class, state, ER, Gantt, and the newer beta types. This is a coverage claim about diagram families, not complete feature/configuration/rendering equivalence. External plugins such as ZenUML are unsupported. Layout positions and routes differ; Mermaid theme colors do not carry over; arbitrary HTML labels and JavaScript click callbacks are unsupported. Subgraphs keep their own direction even when connected outside, and responsive rendering can change diagram direction unless disabled. [compatibility](https://pele.run/compatibility).

Independent Node probes against the unmodified 1.7.0 tarball established:

- `supports('flowchart LR\n A[[')` returns `true`, while `render()` throws a syntax error. `supports()` detects registered diagram types, not successful parsing or fidelity.
- Literal `List<T>` becomes `List`; HTML entity-encoded brackets survive. HTML table labels become concatenated text. This confirms [issue #31](https://github.com/obsidianmd/pele/issues/31), but **does not establish a unique SmartDiffChecker regression**: its current validator and Mermaid rendering also constrain these labels.
- `$$\\alpha^2 + \\beta^2 = 1$$` appears as literal text. Math typesetting is an unimplemented feature, reported in [issue #36](https://github.com/obsidianmd/pele/issues/36).
- Sequence footers are configurable: `{config:{sequence:{mirrorActors:false}}}` changed a fixture from two footer actors to none. `{config:{sequence:{wrap:true,width:100}}}` changed the same long-message fixture from 499×167 to 256×251. These options need an explicit adapter; a Mermaid initialization object is not a Pele render-options object.
- `config.sequence.messageFontSize`, `actorFontSize`, and `noteFontSize` produced unchanged dimensions and message font size. Source does not read those keys. `options.fontSize:24` changed the actor base font to 24 and message font to 21. Supported sequence settings also include `rightAngles`, `actorMargin`, `height`, `messageMargin`, `noteMargin`, `boxMargin`, `messageAlign`, `showSequenceNumbers`, and `hideUnusedParticipants`. [sequence renderer](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/src/diagrams/sequence/render.ts#L216), [sequence parsing](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/src/diagrams/sequence/index.ts), [upstream tests](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/tests/render/sequence.test.ts).

Other open reports at inspection include dark-theme text contrast with author-set fills [#29](https://github.com/obsidianmd/pele/issues/29), resize-observer loops [#32](https://github.com/obsidianmd/pele/issues/32), subgraph edge crossings [#3](https://github.com/obsidianmd/pele/issues/3), sequence wrapping [#18](https://github.com/obsidianmd/pele/issues/18), and self-message overlap [#19](https://github.com/obsidianmd/pele/issues/19). These are reporter claims unless independently reproduced; a linked open PR is not a released fix.

## Security and privacy

The design deliberately escapes text, filters style properties and URL schemes, ignores callbacks, and limits source/output size. Independent package probes found no script element from a script-shaped label, no link from a `javascript:` click target, and no callback link; an HTTPS click target was retained. These narrow probes are not a security audit. [URL filtering](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/src/util/url.ts), [style filtering](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/src/svg/theme.ts).

The important host responsibilities are explicit: icons return trusted raw SVG markup; errors must be inserted as text; internal link names need application navigation policy; render options stay controlled by the application. Remote images are enabled by default and can make requests when displayed. A package probe confirmed an HTTPS image was present by default and removed by `{links:false,images:false}`. Keep the application's sanitizer/navigation/privacy boundary when switching engines. [security documentation](https://pele.run/security), [SECURITY.md](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/SECURITY.md).

Defaults are 50,000 source characters, 4,000,000 SVG characters, and 5,000 edges for flowchart/agentflow. The output check happens **after generation**; it is not a rendering deadline or complete CPU/memory bound. A terminable worker is upstream's suggested time-limit mechanism. [core limits](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/src/core.ts).

## Maturity and testing

The repository was created on **2026-10-05**; this renderer's npm releases start at **1.0.1 on October 6**, reaching 1.7.0 thirteen days later. npm's 2020 `1.0.0` entry is an unrelated LavaMoat Node-hardening experiment and must not be mistaken for six years of diagram-renderer maturity. GitHub's contributor snapshot showed 195 commits from `kepano` and one from another contributor: clear ownership and activity, but maintenance is concentrated. [repository metadata](https://api.github.com/repos/obsidianmd/pele), [npm versions](https://registry.npmjs.org/pele), [contributors](https://api.github.com/repos/obsidianmd/pele/contributors).

Source inspection found substantial parser-oracle/differential fuzzing, corpus/stress tests, and hostile-input checks; the inspected `main` tree contains 292 test/spec files, including 31 security-named tests and 32 oracle tests. Compatibility skip manifests explicitly omit many Mermaid DOM/layout/theme tests because Pele owns a different renderer. This is thoughtful syntax/security coverage, not proof of equal visual output. CI and release workflows typecheck, test, build, and check packed entry points; the 1.7.0 release workflow and inspected `main` CI were successful. I did not independently rerun the complete upstream suite. [contributing](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/CONTRIBUTING.md), [flowchart oracle](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/tests/flowchart/oracle.test.ts), [security checks](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/tests/render/security.test.ts), [sequence exclusions](https://github.com/obsidianmd/pele/blob/8603bf3313add9143cd417015d4a6bd6c522dada/tests/compat/sequence/SKIPPED.md), [CI run](https://github.com/obsidianmd/pele/actions/runs/39320322278).

The website advertises roughly 230 kB gzip and up to 500× speedup. Those are upstream claims, not measurements in this report. Its current benchmark uses headless Chrome, inserts both SVG outputs, compares diagrams accepted by both, and has several warm samples; it still does not establish this application's initial loading, final painted frame, large-graph readability, or lifecycle behavior. Evaluate the intended import path and actual corpus independently. [upstream claims](https://pele.run/), [benchmark source](https://github.com/obsidianmd/pele/blob/52b5c9cc8020fd157599eb601bcc930134332331/scripts/bench-mermaid.mjs).
